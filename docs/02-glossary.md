# 02. Glossary

Terms are listed alphabetically. Where a term has a precise technical meaning inside recast, that meaning is the one defined here.

| Term                                    | Definition                                                                                                                                                                                                                                                   |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ABI**                                 | Application Binary Interface. The binary-level rules for calling functions and laying out data (register use, struct layout, name mangling). Two languages must agree on the ABI to call each other.                                                         |
| **Alias / aliasing**                    | Two or more names (pointers or references) that can reach the same memory location.                                                                                                                                                                          |
| **Alias analysis**                      | Static analysis that computes which pointers may refer to the same memory. Also called points-to analysis.                                                                                                                                                   |
| **Arena / handle strategy**             | A memory strategy that stores objects in a vector (the arena) and refers to them by integer index (the handle) instead of by pointer. Used to express cyclic or shared structures in safe Rust without reference counting. Tier T1.                          |
| **AST**                                 | Abstract Syntax Tree. The tree Clang produces from source code.                                                                                                                                                                                              |
| **Borrow**                              | In Rust, a temporary reference to a value that does not take ownership. Shared borrows (`&T`) allow many readers; a mutable borrow (`&mut T`) allows exactly one writer and no readers.                                                                      |
| **Borrow checker**                      | The part of the Rust compiler that enforces borrowing and lifetime rules at compile time.                                                                                                                                                                    |
| **Characterization test**               | A test generated by observing the original program's behavior on recorded inputs, then asserting the translated program matches. Used when a project has few existing tests.                                                                                 |
| **Clang**                               | The C/C++ front end of the LLVM project. recast uses it to parse and type-check input.                                                                                                                                                                       |
| **Compilation database**                | A `compile_commands.json` file listing, for each source file, the exact compiler command used to build it. Needed because C/C++ meaning depends on flags, include paths and defines.                                                                         |
| **Configuration (build configuration)** | A particular assignment of preprocessor macros and platform settings under which the code is compiled. Different configurations compile different code from the same files.                                                                                  |
| **Contract**                            | A user-supplied declaration describing the ownership and nullability of a pointer at an API boundary (for example "parameter `buf` is borrowed, non-null, length given by `len`"). Stored in the contracts file.                                             |
| **Differential testing**                | Running the original and the translated program on the same inputs and comparing observable behavior.                                                                                                                                                        |
| **Equivalence**                         | Two programs produce the same observable behavior for all considered inputs. recast distinguishes _tested_, _fuzzed_, _bounded-proved_ and _proved_ equivalence (see `07-verification-specification.md`).                                                    |
| **Exporter**                            | The C++ component built on Clang LibTooling that reads a translation unit and emits recast's versioned AST schema.                                                                                                                                           |
| **FFI**                                 | Foreign Function Interface. The mechanism by which code in one language calls code in another.                                                                                                                                                               |
| **Flagged item**                        | A function, type or global that recast cannot translate safely. By default it is preserved as a Rust stub that calls the original C/C++ implementation (Tier T4).                                                                                            |
| **Fuzzing**                             | Automatically generating many varied inputs to look for crashes or behavioral differences.                                                                                                                                                                   |
| **Idiom pass**                          | A transformation stage that rewrites correct but verbose Rust (for example index loops) into idiomatic forms (for example iterators), re-verified afterward.                                                                                                 |
| **Interior mutability**                 | Rust types (`Cell`, `RefCell`, `Mutex`, atomics) that allow mutation through a shared reference, with the safety check moved from compile time to run time (or to zero-cost for `Cell` on `Copy` data).                                                      |
| **IR**                                  | Intermediate Representation. recast's own is **TIR**.                                                                                                                                                                                                        |
| **Lifetime**                            | In Rust, the span of code over which a reference is valid. Often inferred; sometimes must be written explicitly.                                                                                                                                             |
| **Lowering**                            | Converting from a higher-level form to a more explicit one (for example Clang AST to TIR).                                                                                                                                                                   |
| **Memory strategy tier**                | One of T0 to T4: the way a given piece of memory use is expressed in Rust. See `06-translation-specification.md`.                                                                                                                                            |
| **Miri**                                | An interpreter for Rust's mid-level IR that detects undefined behavior in `unsafe` code. Used in verification.                                                                                                                                               |
| **Monomorphization**                    | Generating a separate concrete copy of generic or templated code for each distinct set of type arguments.                                                                                                                                                    |
| **Move (C++)**                          | Transfer of a resource's contents from one object to another via move constructor or move assignment, leaving the source in a valid but unspecified state.                                                                                                   |
| **Move (Rust)**                         | Transfer of ownership; the source can no longer be used.                                                                                                                                                                                                     |
| **Nullability**                         | Whether a pointer may be null. Nullable pointers translate to `Option`.                                                                                                                                                                                      |
| **Observable behavior**                 | What an outside party can see: program output, return values, files written, network traffic, exit status, and (for libraries) return values and side effects through the public API. Internal memory layout is not observable unless it crosses a boundary. |
| **Ownership**                           | In Rust, the property that exactly one binding is responsible for freeing a value. In analysis, the inferred answer to "which pointer is responsible for freeing this allocation?"                                                                           |
| **Points-to set**                       | The set of memory objects a pointer may refer to, computed by alias analysis.                                                                                                                                                                                |
| **Provenance (of a TIR node)**          | Metadata recording where a node came from: source location, macro expansion trail and build configuration condition. Not to be confused with pointer provenance in memory models.                                                                            |
| **Report**                              | The machine-readable and human-readable output describing everything recast did, what it established, and what it did not.                                                                                                                                   |
| **Rule**                                | A deterministic translation or analysis step with a stable identifier (for example `TR-203`).                                                                                                                                                                |
| **Safety gate**                         | The final stage that accepts, accepts with notes, or rejects an output according to a policy profile.                                                                                                                                                        |
| **Sanitizer**                           | A compiler-inserted runtime checker (AddressSanitizer, UndefinedBehaviorSanitizer, ThreadSanitizer, MemorySanitizer) that detects memory and concurrency bugs.                                                                                               |
| **Shim**                                | A small generated wrapper that adapts one calling convention or ownership convention to another, used at language boundaries.                                                                                                                                |
| **Slice**                               | In Rust, a view (`&[T]` or `&mut [T]`) over a contiguous run of elements carrying its length. The safe counterpart to C's pointer-plus-length pairs.                                                                                                         |
| **Tier (T0 to T4)**                     | See memory strategy tier. T0 zero-cost safe; T1 index or handle based; T2 runtime-checked safe; T3 contained `unsafe`; T4 flagged and preserved via FFI.                                                                                                     |
| **TIR**                                 | recast's Intermediate Representation. Defined in `04-ir-specification.md`.                                                                                                                                                                                   |
| **Translation unit (TU)**               | A source file after preprocessing (with all its included headers). The unit Clang compiles.                                                                                                                                                                  |
| **UB**                                  | Undefined Behavior. Operations for which the language standard imposes no requirements (for example signed integer overflow in C++, out-of-bounds access). Compilers may assume UB never happens.                                                            |
| **UB reliance**                         | A situation where the original program's observable behavior depends on a specific compiler's handling of UB. recast detects and reports these.                                                                                                              |
| **Unsafe (Rust)**                       | A Rust block or function in which the programmer, not the compiler, guarantees certain memory-safety invariants.                                                                                                                                             |
| **USR**                                 | Unified Symbol Resolution. A stable string Clang assigns to a declaration across translation units. recast uses USRs to identify items.                                                                                                                      |
| **Verification ladder**                 | The ordered set of checks V0 to V5 described in `07-verification-specification.md`.                                                                                                                                                                          |
