# M1 Audit

Status of the M1 milestone: C subset translator for L0. The milestone exit state is `v1.1.12`. A second pass over the claims the documents make about the pipeline, performed 2026-10-26, found the defects recorded in the first table under [Findings and repairs](#findings-and-repairs); those repairs are tagged `v1.1.13` and `v1.1.14`. A third pass, performed 2026-10-27, probed every claim again with small programs run through the real exporter, analyzer, translator and verifier; each defect it reproduced is repaired in its own commit and tag, `v1.1.15` to `v1.1.27`, and `v1.1.28` is the style pass that makes `rustfmt` and `clippy` pass.

## Scope

- Scalar types, arithmetic, control flow, structs by value, fixed arrays, string literals, enums and constants.
- CFG construction, liveness, definite assignment, and the M1 undefined-behavior checks.
- Translation at T0, with `#![forbid(unsafe_code)]` and no generated `unsafe`.
- V0 compilation, V2 differential execution, property sweeps and mutation testing.
- The L0 corpus under `corpus/l0/`.
- Failure behavior: every construct outside the subset must be refused with a message, never translated into different behavior.

## Exit criteria

| Criterion                                                             | Result                                             |
| --------------------------------------------------------------------- | -------------------------------------------------- |
| 100% of the L0 corpus translates at T0 with 100% differential pass     | 10 of 10 cases; 174 of 174 calls agree with the C original |
| Property tests on integer arithmetic run 10^6 cases without divergence | 3 sweeps of 1,000,000 inputs, all passing          |
| Mutation kill rate on the L0 subset at least 95% at V2                 | 105 of 105 generated mutants killed (100%)          |

`bash ci/m1-exit.sh` reproduces the table. It runs the real exporter, lowers to TIR, translates, and verifies each case against clang-compiled C with `-O1`. The same script with `-fsigned-char` added to each case's compile command passes the same criteria, which covers a target whose `char` is signed.

## Implementation notes

- The analyzer derives a basic-block CFG from TIR, computes liveness over local names, and runs definite assignment across branches. Missing assignments before use are reported as `UB-005`.
- Interval analysis reports `UB-001` (signed overflow), `UB-007` (invalid shift count) and `UB-008` (division by zero or `MIN / -1`) where the interval proves the condition.
- Definite assignment treats a C parameter as assigned at entry. A parameter assigned in the body is emitted with `mut`.
- Generated signatures stay on one line when they fit within 100 columns; longer signatures use one parameter per line. This matches the project formatter width and avoids churn from `rustfmt`.
- The generated crate declares `#![forbid(unsafe_code)]` and allows `dead_code`, `non_camel_case_types`, `non_snake_case` and `unused_labels` because C identifiers, exported-only functions and loop labels left over after lowering routinely trip those lints.
- A loop whose body contains `continue` is emitted as a labeled block inside a labeled `loop`. Both labels are needed: `continue` leaves the block so the step still runs, and `break` cannot be written without a label inside a labeled block (E0695).
- A `default` arm that is not last is emitted last. `_` matches everything, so keeping C's order would make every later case unreachable.
- A switch arm owns the statements clang leaves as siblings of its label, not only the label's sub-statement. `break`, `return` and `continue` end an arm, and a statement that belongs to no arm refuses the switch instead of being dropped.
- An integer literal carries its Rust type when Rust cannot infer the C type: a value outside `i32`, or an unsigned value stored as a negative bit pattern. The printer spells such a value at the width its suffix names.
- A cast of a constant folds to the value C produces at the target width, so `(unsigned char)300` is 44.
- A statement that is a cast to `void` becomes a discard, printed as `let _ = expr;`.
- A cast on the left of `<`, `<=` or `<<` is parenthesized, because Rust reads `x as u32 < y` as generic arguments.
- A subscript accepts a local array, a slice parameter, an array field of a value, or an element of an array of arrays.
- A compound shift lowers through the same helper as the binary shift, so an out-of-range count keeps the `UB-007` panic.
- Constants keep the value their type means: signed values keep their sign, unsigned values keep their value. A 64-bit unsigned value above `i64::MAX` keeps its bit pattern.
- An anonymous record or enum takes the name of the typedef that declares it; a type with neither is `Unknown`.
- The V2 driver passes a derived slice length at the position of the `size_t` parameter it belongs to, spells a string argument's elements out when the target's `char` is signed, builds an array argument from its elements, and spells a typedef by its alias.
- Mutation testing mutates comparison direction and arithmetic operators. A mutant killed by compilation counts as killed; the mutation report distinguishes the two causes.

## Remaining limitations

- Expression-position `++` and `--` are refused ("only translated as a statement"), as are the comma operator and an assignment used as a value. Document 06 section 11 specifies all three for the full system; M1 supports the statement forms only.
- A `switch` that falls through with statements is refused (document 06 section 10.2), as is a `switch` with a statement outside every case (a declaration before the first label). A `break` in the middle of an arm is refused; only a trailing `break` is supported.
- The property sweeps cover `add`, `mul` and `wrap_add`. Other integer functions are covered by explicit calls and mutation, not by a 10^6 sweep.
- Mutation is operator-level and samples at most 24 mutants per case. It can generate an equivalent mutant (`+ 0` where the operand is zero), so a survivor is evidence to inspect, not proof of a test gap. The corpus avoids shapes where such a mutant would hide a defect.
- The V2 driver prints an integer argument as an unsuffixed literal, so a case whose argument does not fit the parameter's Rust type fails in `rustc` rather than as a case error.
- A compound assignment or `++` on a subscripted place renders the base twice (`x[f()] += 1`); with pure functions this is unobservable inside M1.
- `long double`, bitfields, unions, variadic user functions, function pointers and heap ownership are outside the M1 corpus.
- `break` and `continue` are supported in the TIR and exporter paths exercised by the corpus; `goto` is not.
- Mutable globals need the T1 ownership model and are refused. At the M1 exit state a pointer is accepted only as a `(pointer, size_t)` slice pair; [`audits/m2.md`](m2.md) records the pointer support that starts with `v1.2.0`.
- The corpus is small and hand-written. Scale evidence starts with the M2 corpus.
- The documents, the corpus descriptions and the code were reviewed together before the tags were written.

## Findings and repairs

### Second pass, 2026-10-26

| Class | Finding                                                                                                                                  | Repair                                                                                           | Tag        |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ---------- |
| P1    | Definite assignment reported `UB-005` for a local only a returning branch could leave unassigned: `if (c) { x = 1; } else { return 0; } return x;` was flagged, and so was code after a `break`. | Paths merge only where they reach the join, and a statement that cannot fall through ends the path. | `v1.1.13`  |
| P1    | A `continue` in a `for` or `do`/`while` body that also contained a `break` emitted an unlabeled `break` inside a labeled block, which Rust rejects (E0695); the generated crate did not compile. | The loop carries a label and the `break` targets it.                                             | `v1.1.13`  |
| P1    | A C `switch` whose `default` is not last emitted `_` first, so every later case was unreachable in the generated `match`.                 | The `default` arm is emitted last, which preserves C's meaning because M1 refuses fallthrough with statements. | `v1.1.13`  |
| P1    | The V2 driver emitted a string argument as `b"..."`, which has element type `u8`, while a target with a signed `char` translates the parameter to `&[i8]`. The corpus passed where `char` is unsigned and failed on the x86-64 CI runner. | The driver spells the elements out when the element is signed; a unit test pins both spellings.  | `v1.1.13`  |
| P2    | The V2 driver appended a derived slice length at the end of the C call instead of the `size_t` parameter's own position, so `scan(a, n, limit)` was compared against a different call. | The length is emitted where the parameter that carries it appears.                              | `v1.1.13`  |
| P3    | The document claimed the signed-`char` check ran through a `ci/m1-exit.sh` wrapper, which changes the C compilation but not the exporter's `LangOpts`, where `char_signed` comes from. | The row now says what is run: every L0 case with `-fsigned-char` in its own compile command.    | `v1.1.14`  |
