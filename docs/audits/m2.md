# M2 Audit (in progress)

M2 is the heap-and-pointers milestone. It is **in progress**: the exit criteria in [`project/roadmap.md`](../project/roadmap.md) are not met, and this page tracks each build point, what it covers, what it refuses, and the evidence for the claims it makes.

## Scope

Document 11 defines M2 as: `malloc`/`free`; pointers to single objects and arrays; linked lists and trees; `const` correctness; `char *` strings; output parameters. The analysis and translation work behind that list is points-to analysis with a Steensgaard fallback, ownership constraints through the solver, nullability and extent facts, libc models, T0 to T2 output, the runtime modules `bytes`, `arena`, `checked`, `ub` and `numeric`, `UB-002`, `UB-003`, `UB-004`, `UB-006`, `UB-012` and `UB-015`, the L3 ground-truth suite, the L7 soundness harness, and idiom pass v1.

## What the pointer step translates

- A `T *` parameter with no `size_t` after it is one object, not a slice: `const T *` becomes `&T` and `T *` becomes `&mut T`. The `(pointer, size_t)` slice pair keeps its M1 translation.
- `*p` is a Rust dereference, both as a value and as an assignment target (`*p = v`, `*p += v`, `(*p)++`).
- `&x` is a borrow; it is `&mut x` when the pointer's pointee is not const. A local or parameter whose address is taken as a mutable pointer is emitted with `mut`, which is what `&mut` requires.
- A pointer local (`int *p = &n;`) is a reference local. Passing a pointer to a call copies it in C, so a place that already holds one is reborrowed (`&mut *p`) and the caller keeps its pointer for the next call.
- An array argument becomes `&a[..n]` for a slice parameter, the borrow of exactly the elements the count names; for a one-object pointer parameter it becomes `&mut a[0]`, the borrow C's decay produces.
- A call to a slice function does not pass the length, because the Rust parameter is the slice and the callee reads `len()`. The argument is narrowed to that length: `sum(a, 2)` on a four-element array is `sum(&a[..2])`, and `sum(&a[1], 2)` is `sum(&a[1..][..2])`, so the callee's `len()` is the count the C call passed rather than the array's size.
- A mutable slice argument is a place the V2 driver owns: it is declared as an array on both sides, passed as `&mut aN`, and every element is printed after the call, so a write through the slice is part of the differential.
- Adding const to the pointee at a use site (`int *` to `const int *`) is left to Rust's coercion. Any other pointer cast is refused.
- The V2 driver owns a place for every pointer argument, passes its address, and prints the place after the call. A non-const pointee is observed, so a write through an output parameter is part of the differential rather than invisible.

### Assumption

A slice parameter is assumed to be **exactly its length argument**: the Rust slice's `len()` stands for the C `size_t`, so a caller outside a translated crate that passes a longer buffer than the count gives the callee a longer slice. Every call the translator emits narrows the slice to the count, so the assumption holds inside a translated crate.

A pointer parameter is assumed **non-null, valid and pointing at one object**. Every call the translator emits passes a borrow of a live place, so the assumption holds inside a translated crate, and `&T` states it to the compiler. A C caller outside the crate that passes `NULL` breaks the assumption; making that boundary explicit is the nullability work below, not a claim this build point makes.

## Refusals

Every construct below fails with a message that names the reason; none of them translates to something with different behavior. The stage that refuses it is named because that is what `ci/m2-refusals.sh` checks:

| Construct                                              | Refused by           | Message                                                                    |
| ------------------------------------------------------ | -------------------- | -------------------------------------------------------------------------- |
| `p->field`                                             | exporter/validator   | `pointer member access is outside the M1 subset`                            |
| Pointer arithmetic (`p + 1`)                           | exporter/validator   | `operands of + need an explicit implicit cast`                              |
| `malloc` and `free`                                    | exporter/validator   | `unresolved callee malloc cannot enter the M0 pipeline`                     |
| A function returning a pointer                         | translator           | `a function returning a pointer needs an explicit lifetime`                 |
| Pointer comparison and a pointer used as a condition   | translator           | `... needs the M2 ownership model`                                          |
| A cast that changes the pointee, and a null pointer    | translator           | `a pointer cast that changes the pointee needs the M2 ownership model`      |
| A cast from a pointer to an integer                    | translator           | `a cast from a pointer is outside the M2 pointer step`                      |
| A mutable file-scope variable                          | translator           | `mutable file-scope variables need the T1 ownership model`                  |
| A record pointee in a case call                        | V2 driver            | `a pointer whose pointee is not a scalar is the next M2 step`               |
| Reassigning a pointer parameter (`p = q`)              | translator           | `p is a pointer parameter; assigning it another pointer needs the M2 ownership model` |
| Dereferencing a slice parameter (`*out` in a group)    | translator           | ``out is a slice parameter, so `*out` reads it as one object; the M2 extent facts are needed`` |
| Assigning to a slice length (`n = 1`)                  | translator           | `n is the length of slice a; assigning it needs the M2 extent facts`        |
| A C name that is a Rust keyword (`int use(...)`)       | translator           | `` `use` is a Rust keyword, so a C name that collides with one needs the M2 rename pass `` |
| One pointer passed to two mutable parameters           | translator           | `p is passed to two mutable parameters, which C allows to alias; the M2 ownership model is needed` |

The record-pointee line is about the harness only: `int first(struct P *p)` translates to `pub fn first(p: &mut P)`, and the driver refuses to own a record behind the pointer yet. `NULL` is refused as a pointer-typed integer constant, so it reports the pointee-cast message. `char *` beyond the `(pointer, size_t)` slice pair is refused by the same checks as any other pointee the step does not cover.

## Remaining M2 work

- Record and array pointees, `p->field`, and a driver that owns a record behind a pointer.
- Pointer returns with explicit lifetimes, and the region facts they need.
- Nullability: `Option<&T>`, null comparisons, `UB-002`, and the contract at an external boundary.
- The heap: `malloc`/`free` into `Box`, arrays into `Box<[T]>`/`Vec<T>`, and the allocation-failure policy.
- Linked lists and trees: recursive records, `Option<Box<Node>>`, and iterative `Drop`.
- `char *` strings with length and terminator handling beyond the M1 slice.
- Pointer arithmetic with extent and bounds facts.
- `UB-003`, `UB-004`, `UB-006`, `UB-012`, `UB-015`.
- Points-to analysis with the Steensgaard fallback; ownership constraints through the solver; libc models under `models/`.
- The L3 ground-truth suite, the L7 soundness harness and idiom pass v1.
- The exit criteria: cJSON at 70% T0/T1, zero L7 contradictions, the vulnerability corpus, and the 5-minute 100k-line budget.
