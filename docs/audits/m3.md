# M3 Audit (opening)

M3 is the verification-and-gate milestone. This is the **opening audit**: it records what the tree contains at `v1.3.0`, which M3 build items already exist, which are missing, and the order the missing ones will be built in. The exit criteria in [`project/roadmap.md`](../project/roadmap.md) are **not** met, and nothing below claims them.

## Status at opening

- The workspace version is `1.3.0`; `recast version` reports `recast-ast/1` and `tir/1` at schema version 1, and the M1 rule set (`UB-001`, `UB-005`, `UB-007`, `UB-008`).
- Translation emits **T0 only**. There is no tier map and no T4 fallback, so gate rules about higher tiers have nothing to act on yet.
- Verification is **V0** (the generated crate compiles), **V2** (a generated C driver and a generated Rust driver run the same calls, plus deterministic property sweeps) and **operator mutation** against the V2 baseline. There is no V1 static-hygiene rung, no V3 fuzzing and no V4 sanitizer or Miri run.
- The CLI has `init`, `export`, `analyze`, `translate`, `verify`, `version` and `doctor`. There is no `run`, `gate`, `report`, `explain` or `diff`.
- `--profile` is parsed and unused; `recast init` writes no `[gate]` section; the only `recast.toml` fields read are the compile-commands path and the project name.
- `recast-case/1` accepts a `test_command`, but nothing runs it.
- `recast-report/1` exists only as prose in [`architecture/verification.md`](../architecture/verification.md) section 6. `verify --format json` prints a one-line summary, not the schema.
- Evidence classes and the claim-language lint do not exist.
- `recast-interop` and `recast-orchestrator` are module documentation only (`//!` and no items).
- Determinism is checked by `ci/fast.sh` (two full runs must be byte-identical), outside the gate; there is no GATE-005 run over the report and explain artifacts, because neither exists.

## Order of work

The order follows dependencies, not the roadmap's bullet order:

1. **`recast-report/1` first.** Nothing else can be gated or frozen until one artifact holds verdicts, evidence, skipped rungs, assumptions and the limitations statement. `verify` writes it; the human `report.md` renders from it.
2. **`gate`.** Profiles load from `recast.toml`, rules `GATE-001` to `GATE-009` are evaluated where T0 makes them meaningful, verdicts and exit codes are fixed. The `audit` profile runs everything and rejects nothing.
3. **`run`.** One command over export, analyze, translate, verify and report, with `--format json` and the documented default workflow.
4. **V3.** A structure-aware input decoder built from TIR types, a fixed iteration or CPU budget, recorded seed corpus and RNG seed, and triage classes (`translation-bug`, `original-UB`, `nondeterminism`, `unknown`).
5. **V4.** ASan/UBSan (and MSan where available) on the original; overflow checks, debug assertions and Miri on the translated code; the sandbox runner both need.
6. **SARIF, `explain`, `diff`, evidence classes, claim lint, schema freeze.** These consume the report and the tier map; they are last because they cannot be correct before either exists.

## Dependencies and non-claims

- **M2 exit criteria remain open.** The gate can measure the subset M2 now translates; it must report that scope rather than imply M2 or cJSON coverage. [`audits/m2.md`](m2.md) is the record of what the pointer step refuses.
- **Tiers.** With T0-only output, profile rules about maximum tier, T3 `SAFETY` comments and T4 boundary tests can be implemented and unit-tested but not exercised on real translations. The audit does not pretend otherwise.
- **V1 naming.** The verify crate's module doc calls its optional original-test rung V1 and the generated-crate compile rung V0. This audit uses document 07's rung names; the M3 V1 is static hygiene (`clippy`, unsafe inventory, layout asserts, forbidden patterns).
- **Performance.** No claim of the M2 100k-line budget or the M3 mutation threshold is made; both are measured work, not present work.
